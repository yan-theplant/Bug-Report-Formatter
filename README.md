# Bug Report Formatter（缺陷报告规范器）

Claude Code skill：把零散、口语化的 bug 描述（可带截图/录屏）整理成字段完整、格式统一、
可直接粘进 Jira 的规范报告；必要时直接在 Jira 建票。

> ℹ️ **这是公开脱敏版**：`projects/` 里的 Jira 站点、cloudId、accountId、邮箱、票号已替换为占位符（`<your-site>`、`<YOUR_CLOUD_ID>`、`<accountId-dev-N>`、`<MDX-xxxx>` 等），换成自己项目的值即可使用。

## 解决什么问题

QA 提的票经常被开发打回追问：「上个版本是好的吗？」「另一端呢？」「什么设备什么版本？」「步骤看不懂」。
这个 skill 把这些高频追问点在模板里**定死落位**，从源头挡掉来回拉扯，同时保证缺陷数据规范
（便于看板按模块 / 平台 / 优先级聚合）。

「定死落位」指的是**每一项都要被处理过、写明结论或写明未验证**，不是「答不出就不给报告」——
硬拦截只用在真正需要它的场景（挂回归总票的票），见下面「回归三问」那一行。

另一半问题是**开一张票太慢**：录屏逐帧盲扫、崩溃票放着日志不用去翻画面、同样的版本号每次重问、
两道确认关卡来回等人。这一版把这些都收掉了。

## 核心能力

| 能力 | 说明 |
|---|---|
| **自动分流** | 进 skill 先自行判断走「JMA 版本回归」还是「通用 bug」路线（按票号、产品名、`5.x.xx` 版本号、回归总票等信号），不反问用户 |
| **两种模式** | A = 只出报告文本；B = 报告 + 真实建票（查重 → 建票 → 附件 → 内嵌 → 链接） |
| **录屏自动解析（两阶段）** | 给了 `.mp4/.mov` 就用 ffmpeg 抽帧自己看，按视频里的**实际点击顺序**写英文复现步骤，附件说明带时间点，不用口述。抽帧**先粗扫定区间（≤12 帧）再在区间内密集抽**、每轮批量读，不逐帧盲扫；要精确到某一秒的画面时用 `-ss` 小数秒或帧号并一次抽一批候选点 |
| **崩溃 / 闪退捷径** | 崩溃票不从画面找「哪一帧崩的」：先解 iOS `.ips` / Android logcat，自带 `scripts/parse_ips.py`（判 watchdog kill vs 异常崩溃、算启动后存活时长、定卡点嫌疑、出 Actual 草稿），再用日志时间戳反推录屏位置**只抽 ±5s**。多份日志一起解，堆栈相同即可直接得出回归性结论，省掉装旧包复验 |
| **证据图自动补** | 录屏不算证据到位：按帧定位时间点后**用原生分辨率重抽帧**，拼 before/after 对比图放在视频上方；双端 bug 每个场景拼一张左右对比图（iOS 左 / Android 右，原生像素不缩放）。每侧标 `OS(设备) · build · 时间点`，并**用红框圈出问题部位**；自带 `scripts/side_by_side.py` |
| **优先级带依据** | Highest~**Lowest** 按「用户影响面 × 功能重要性」判定，必须输出一行判定依据；确认是本版本回归则上调一档。法务 / 合规 / 金额正确性一律 Highest（与影响用户数无关）；有 workaround 的主功能问题落 Medium；纯视觉 / 纯文案（含与设计稿的差异）落 Lowest |
| **回归三问（分场景定力度）** | 上个版本是否正常 / 另一端是否复现 / 是否阻塞使用 —— 三问每票都要处理过，未验证写明「未验证」。**但只有挂回归总票的票才硬拦截**：feature testing、单独打的分支包、新需求票都不拦截（没有可比基线），非回归票只保留「另一端是否也有」一问。**任何情况下都不因这三问答不出而不给报告。** 持续部署、无版本号的项目改问「是否新出现」并以「某次验证通过的日期」为参照；连参照物都没有时删行，不留指向空处的 TBD |
| **环境按平台定死** | Web 必填 环境 + 浏览器版本 + URL；APP 必填 环境 + App 版本 + 设备/OS。推断不出就追问，不静默删行 |
| **建票前先查重** | 走 curl + jq 直取字段（比 MCP 快得多），英日双语搜同一现象；**先搜 link 目标票的关联范围**（`issue in linkedIssues(...)`）再放开到全项目，别一上来全项目扫；命中疑似重复就停下来给选项：追评论 / 合并票 / 拆多张，**与文案草稿放在同一条消息里抛出**，只设一道确认关卡 |
| **附件清晰度优先** | 视频**一律去音轨**（与压不压无关）；**≤50MB 直接传原文件**，>50MB 才压且用原生宽度 + 低 CRF——重压会把 UI / console 文字压糊。压完自检文字是否仍可读，不划算就传原文件 |
| **上传 ≠ 内嵌** | 走 API 时两者是两步：上传拿数字 id → 换 media UUID（303 Location）→ ADF `mediaSingle` 靠左 + 内层真实像素。改正文前先读回，避免把别人刚拖进去的附件冲掉 |
| **正文链接可点** | 走 API 建票时正文里的裸 URL 和票号只是纯文本。建完票读回 ADF，给每个 URL / 票号补 `link` mark 再写回——Slack 线程的 `?thread_ts=`、Figma 的 `?node-id=` 一律保留，尾部标点不吃进 href（用 RFC 3986 的 ASCII 字符类 + 括号配平，中文正文和日文紧贴 URL 都不会截错） |
| **素材默认全用上** | 用户给了的截图 / 录屏默认全部用上，skill 的默认规则不得静默丢弃：单端 bug 的另一端素材作为「正确行为对照」附上。抛给用户的选项必须是单一维度，已经确定的事不问第二遍——但仍要落进字段 |
| **上下文记进 memory** | build 号 / 当期 link 目标 / 经办人偏好写进 `bug-report-context.md`，作为默认值抛出，不每次重问；用户给了新值立刻覆盖写回 |
| **项目级配置** | `projects/<KEY>.md` 存各项目专属约定，冲突时以项目文件为准 |

## 固定规则

- **标题、Steps、Expected、Actual 一律英文**；字段名与备注可用中文
- **UI 文案原文照抄不翻译**（`ログイン`、`注文を確定`）
- 标题格式：`<环境> > <平台(build)> > <功能区> > <具体模块/页面> > <问题>`，必须写出具体出问题的页面
- 绝不臆造信息，缺字段标 `⚠️ TBD` 并在结尾统一追问
- 只客观描述现象，不评价开发、不猜代码原因

## 触发方式

说「写个 bug 报告」「规范化一下这个 bug」「开票」「建 bug」「create bug」，
或 Claude 在测试中撞到 bug 需要记录时自动使用。

## 目录结构

```
bug-report-formatter/
├── SKILL.md                      # 通用流程（分流 → 解析 → 报告 → 建票），always-on
├── references/                   # 按需加载：只在走到对应步骤时才读，省掉每次的读取开销
│   ├── crash-bugs.md             #   崩溃 / 闪退票的完整规则（日志判读、时区换算、字段落位）
│   ├── evidence-images.md        #   拼图与圈注的完整规则（原生像素、降级路径、字体陷阱）
│   └── jira-mechanics.md         #   Jira 写操作机制（失败处理、上传压缩、ADF 内嵌、补 link mark）
├── scripts/
│   ├── parse_ips.py              #   解析 iOS .ips：崩溃性质 / 存活时长 / 卡点 / 跨 build 比对
│   └── side_by_side.py           #   按原生像素拼接证据图 + 标注 + 红框圈注
└── projects/
    ├── MDX.md                    # 麦当劳日本 app/web：两套版本号、功能区白名单、回归总票、经办人
    └── JMA.md                    # 已停用，仅记与 MDX 的差异
```

> `SKILL.md` 只放**决策性规则**，机制细节都在 `references/` 里按需加载 —— 默认的 A 模式
> （只出报告、无崩溃日志）压根不会读到 Jira 写机制那 15KB。

## 安装

```bash
git clone git@github.com:yan-theplant/Bug-Report-Formatter.git
cp -R Bug-Report-Formatter/bug-report-formatter ~/.claude/skills/
```

依赖（按需）：

| 依赖 | 用途 | 装法 |
|---|---|---|
| `ffmpeg` / `ffprobe` | 读录屏抽帧、去音轨、压视频 | `brew install ffmpeg` |
| `jq` | 查重结果解析 | `brew install jq` |
| `sips` | 取图片原生像素尺寸、压图 | macOS 自带 |
| Python `Pillow` | 拼证据图 + 圈注（`scripts/side_by_side.py`） | `pip3 install Pillow` |
| `python3` | 两个脚本；解析 `.ips` 只用标准库 | macOS 自带 |

建票需要在 Claude 的 memory 里配好 `jira-credentials`。
首次使用时 skill 会自己跑一次环境预检，缺什么一次性列出来。

## 换成你自己的项目

1. 把 `projects/MDX.md` 复制成 `projects/<你的项目KEY>.md`
2. 替换里面的占位符：`<your-site>` / `<YOUR_CLOUD_ID>` / `<your-email>` / `<accountId-dev-N>` / `<MDX-xxxx>`
3. 按你团队的实际约定改：标题风格、环境段取值、版本号体系、功能区白名单、回归总票命名、查重关键词对
4. `SKILL.md` 第 0 节的分流信号也换成你项目的产品名 / 票号前缀 / 版本号形态

`SKILL.md` 本身是项目无关的通用流程，通常不用改。
