# Bug Report Formatter（缺陷报告规范器）

Claude Code skill：把零散、口语化的 bug 描述（可带截图/录屏）整理成字段完整、格式统一、
可直接粘进 Jira 的规范报告；必要时直接在 Jira 建票。

> ℹ️ **这是公开脱敏版**：`projects/` 里的 Jira 站点、cloudId、accountId、邮箱、票号已替换为占位符（`<your-site>`、`<YOUR_CLOUD_ID>`、`<accountId-dev-N>`、`<MDX-xxxx>` 等），换成自己项目的值即可使用。

## 解决什么问题

QA 提的票经常被开发打回追问：「上个版本是好的吗？」「另一端呢？」「什么设备什么版本？」「步骤看不懂」。
这个 skill 把这些高频追问点在模板里**定死为必填**，从源头挡掉来回拉扯，同时保证缺陷数据规范
（便于看板按模块 / 平台 / 优先级聚合）。

## 核心能力

| 能力 | 说明 |
|---|---|
| **自动分流** | 进 skill 先自行判断走「JMA 版本回归」还是「通用 bug」路线（按票号、产品名、`5.x.xx` 版本号、回归总票等信号），不反问用户 |
| **两种模式** | A = 只出报告文本；B = 报告 + 真实建票（查重 → 建票 → 附件 → 内嵌 → 链接） |
| **录屏自动解析** | 给了 `.mp4/.mov` 就用 ffmpeg 抽帧自己看，按视频里的**实际点击顺序**写英文复现步骤，附件说明带时间点，不用口述 |
| **优先级带依据** | Highest/High/Medium/Low 按「用户影响面 × 功能重要性」判定，必须输出一行判定依据；确认是本版本回归则上调一档 |
| **回归三问必出** | 上个版本是否正常 / 另一端是否复现 / 是否阻塞使用 —— 未验证也要写明「未验证」，绝不留空 |
| **环境按平台定死** | Web 必填 环境 + 浏览器版本 + URL；APP 必填 环境 + App 版本 + 设备/OS。推断不出就追问，不静默删行 |
| **建票前先查重** | 走 curl + jq 直取字段（比 MCP 快得多），英日双语搜同一现象；命中疑似重复就停下来给选项：追评论 / 合并票 / 拆多张 |
| **附件先压缩再传** | 视频去音轨缩到 1280、图片 sips 缩放，压完自检文字是否仍可读，不划算就传原文件；内嵌时靠左 + 真实像素尺寸 |
| **项目级配置** | `projects/<KEY>.md` 存各项目专属约定，冲突时以项目文件为准 |

## 固定规则

- **标题、Steps、Expected、Actual 一律英文**；字段名与备注可用中文
- **UI 文案原文照抄不翻译**（`ログイン`、`注文を確定`）
- 标题格式：`<环境> > <平台(build)> > <功能区> > <具体模块/页面> > <问题>`，必须写出具体出问题的页面
- 绝不臆造信息，缺字段标 `⚠️ TBD` 并在结尾统一追问
- 只客观描述现象，不评价开发、不猜代码原因

## 触发方式

说「写个 bug 报告」「规范化一下这个 bug」「开票」「建 bug」「create bug」，
或 Claude 在测试中撞到 bug 需要记录时自动使用。

## 目录结构

```
bug-report-formatter/
├── SKILL.md          # 通用流程（分流 → 解析 → 报告 → 建票）
└── projects/
    ├── MDX.md        # 麦当劳日本 app/web：两套版本号、功能区白名单、回归总票、经办人
    └── JMA.md        # 已停用，仅记与 MDX 的差异
```

## 安装

```bash
git clone git@github.com:yan-theplant/Bug-Report-Formatter.git
cp -R Bug-Report-Formatter/bug-report-formatter ~/.claude/skills/
```

依赖（按需）：`ffmpeg`（读录屏 / 压视频）· `jq`（查重解析）· `sips`（macOS 自带，压图）。
建票需要在 Claude 的 memory 里配好 `jira-credentials`。

## 换成你自己的项目

1. 把 `projects/MDX.md` 复制成 `projects/<你的项目KEY>.md`
2. 替换里面的占位符：`<your-site>` / `<YOUR_CLOUD_ID>` / `<your-email>` / `<accountId-dev-N>` / `<MDX-xxxx>`
3. 按你团队的实际约定改：标题风格、环境段取值、版本号体系、功能区白名单、回归总票命名、查重关键词对
4. `SKILL.md` 第 0 节的分流信号也换成你项目的产品名 / 票号前缀 / 版本号形态

`SKILL.md` 本身是项目无关的通用流程，通常不用改。
