# 证据图：before/after 拼图 · 双端对比图 · 圈注

> `bug-report-formatter` 的参考文件。**有录屏或双端 bug、真要动手做图时读它**，由 `SKILL.md` 1.7 节触发。

## 总原则

录屏本身不算证据到位——读者得拖进度条才能看到问题。补两类静态图：

### A. before / after 拼图（有录屏时必出）
- **两步走，别直接用 1.5 的帧拼图**：1.5 抽的帧为了省 token 已经 `scale=1500` 缩过，拿它拼图等于违反下面的「不许重采样」。正确做法是——用 1.5 阶段 A/B 的帧序列**只定位时间点**，再按该时间点**用原生分辨率重抽一帧**（不带 `-vf scale`）：
  ```bash
  ffmpeg -v error -ss <秒.毫秒> -i "<video>" -frames:v 1 <scratchpad>/before.png
  ffmpeg -v error -ss <秒.毫秒> -i "<video>" -frames:v 1 <scratchpad>/after.png
  ```
  ⚠️ **用 `-ss` 的小数秒写法，别用 `mm:ss`**，并且**一次抽一批候选点再一起挑**——秒级 seek 抽不中每秒都在变的数字（倒计时、时钟），实测为此反复试了 9 次。写法与批量循环见 **1.5 节「亚秒 / 精确到帧的取图」**。
- 各取「触发前」与「触发后」一帧，**按原生像素左右拼接**，每侧标上参照标识 + 画面时间：有版本号体系写 build（如 `1712 · 0:03` / `1723 · 0:11`），无版本号体系写日期或视口宽度（如 `1440px · 0:03` / `768px · 0:11`）。
- 拼图**放在视频上方**，让人不用播放就看到缺陷。
- 🔴 **每一侧都要标出「这是哪台设备 / 哪个 OS」**（团队反馈，2026-09-03：「可以在每个录屏上方标注上对应的设备，方便开发知道每个录屏对应的是哪个设备」）。同一张票里有多支录屏 / 多台设备时尤其必须标，否则开发对不上号。标注格式：`Android 12 (Pixel 4 XL) · 462 · 0:07`，即 **OS(设备型号) · build · 时间点**。
- 视频仍要**完整嵌入**，不要用截图或短片段替代；需要的话额外加一段剪辑版，标清 `Video 1 — side-by-side` / `Video 2 — full recording`。
- **没装 ffmpeg 的降级**：拼图做不出来（1.5 步骤 1 已经问过用户装不装）。此时**不要卡住**——附件说明里标 `⚠️ TBD 拼图未做（本机无 ffmpeg）`，正文照常出，并在结尾追问里带上一句「装了 ffmpeg 我可以补 before/after 拼图」。

### B. 双端对比图（iOS + Android 都涉及时必出）
不要把两端截图作为两张独立图片贴上去，**每个测试场景拼成一张左右对比图**（iOS 左、Android 右），一个场景一张。

- **原生像素粘贴、不缩放**：各图按自身像素尺寸顶部对齐，画布高度取较高的那张。**绝不为了等高而缩放**（会重采样、发虚），宽高比必须与原图 1:1。
- 加一个场景小标题 + 每列标注平台 + build，如 `iOS 5.5.40 (1685)` / `Android 5.5.40 (1334)`。
- 两端数据/门店/账号不同但被测 UI 相同时，在标注里写明（如 `*different store, same UI`）。
- ⚠️ 标注避开字体渲染不了的字符：`→` 在 Helvetica/Arial 里是豆腐块，用 `>` 或 `-`。

### C. 圈注出问题的部位（**拼图必做，不是可选美化**）

拼图只是把两张图放在一起，读者还得自己找差异在哪。**必须在图上把有问题的部位圈出来**（团队反馈，2026-09-03：「建议截图对比可以帮忙粗略标注出有问题的部分」，并直接示范了红框 + 箭头的做法）。

- **粗略就够，不要求精细**：一个红框圈住出问题的元素，两侧对应元素各圈一个，需要时加一条箭头把两侧连起来。
- 用 Pillow 画：`ImageDraw.rectangle(xy, outline=(255,0,0), width=<按图宽自适应，约 w/300>)`；箭头用 `line` + 一个小三角。**框线宽度要随原图分辨率放大**，手机截图 1170px 宽用 3–4px，桌面 3000px 宽用 8–10px，否则在 Jira 里缩略后看不见。
- 圈注**画在原生尺寸的图上**，再拼接——不要拼完缩放后再画（会和「不许重采样」冲突）。
- 圈的是**现象**不是结论：框住「显示 `580分50秒` 的那块」，不要在图上写「计算错误」这种判断（判断属于 Actual 的文字）。
- 文字标注避开渲染不了的字符（见 B 的最后一条），中文标注要指定能渲染中文的字体，拿不到就只画框不写字。

工具：macOS 上 ImageMagick 常常没装，**用 Python Pillow** 按原生尺寸粘贴 + 圈注（`pip3 install Pillow`）。原生尺寸用 `sips -g pixelWidth -g pixelHeight <file>`。iOS 模拟器截图 `xcrun simctl io <UDID> screenshot out.png`；Android `adb -s <serial> exec-out screencap -p > out.png`。

本 skill 自带拼图 + 圈注脚本，省得每次现写：
```bash
# 左右拼接，各自标注，红框圈出问题部位（坐标为原生像素）
python3 ~/.claude/skills/bug-report-formatter/scripts/side_by_side.py \
  --out combined.png \
  --left  ios.png     --left-label  "iOS 1766 · 0:49" \
  --right android.png --right-label "Android 1373 · 0:49" \
  --left-box  1085,240,1470,320 \
  --right-box 1740,205,1900,255 \
  --arrow
```
`--help` 看全部参数（`--stack` 上下拼、`--box` 可重复、`--no-arrow`）。

拼好的图走 4.6 / 4.7 的正常上传 + 内嵌流程（靠左、内层 media 用真实尺寸）。
